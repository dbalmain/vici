==============================================================
 vici — every bound feature, one line at a time
==============================================================

 Open this in the harness:   cargo run -p vici-harness

 Harness keys (these bypass the editor entirely):
   F10    quit, always
   F2     hide/show the effect log
   <C-c>  quit, from normal mode only
   :w     save        :q  quit      :q!  discard     :wq  both

 Tick a box by putting the cursor on the space and typing  rx
 — which is itself a test of `r`. Then `u` to untick it.

 The right pane logs every effect the core emits. Watch it: one
 `edit` per keystroke while typing is the thing tree-sitter needs,
 and it is easy to get wrong.

 Nothing here is precious. Break it, then `u` your way back.

 1. MODES
--------------------------------------------------------------

[x] a   insert after the cursor
[x] I   insert at the first non-blank
[x] A   insert at end of row
[x] o   open a row below

      overwrite the middle of this line
[x] v   visual by character
[x] V   visual by line
[x] <Esc> back to normal from any of the above

    Check: after `iabc<Esc>` the cursor sits on `c`, not past it.
    Check: the cursor is a block in normal, a bar in insert.

--------------------------------------------------------------
 4. MOTIONS — find on the row
--------------------------------------------------------------

      select id, name, email from users
[x] f,  forward to the comma
[x] t,  forward, stopping before it
[x] F,  backward to a comma
[x] T,  backward, stopping after it
[x] ;   repeat the last find
[x] ,   repeat it in reverse

      call(one, [two, three], "four") and more
[ ] %   from the start of the row — the first bracket's partner
[ ] %   again — and back, from the closing bracket
[ ] %   with the cursor inside the nested [ ]
[ ] d%  takes both brackets and everything between

    `%` stays on the row, as vi does, and looks for a bracket
    first — so `("four")` matches the parens, not the quotes.
    With no bracket on the row at all it matches a quote pair
    instead, where vi would only ring; on a row with neither it
    rings too. A count does nothing, where vi would jump to a
    percentage of the file.

    Try `%` on one of these checklist rows: the checkbox is a
    bracket pair like any other.

--------------------------------------------------------------
 6. OPERATORS over motions
--------------------------------------------------------------

      delete from here to somewhere over there
[x] dw  delete word           [x] de  delete to word end
[x] d$  to end of row         [x] d0  to start of row
[x] dj  delete two rows — a linewise motion
[x] dG  to the last row       [x] dgg to the first
[x] dt, delete up to a comma, keeping it
[x] cw  change word — behaves like `ce`, no trailing space
[x] ce  change to word end
[x] c$  change to end of row
[x] yw  yank a word, then `p` to paste it
[x] y$  yank to end of row

    `cw` on the last word of a row is the classic irregularity:
    it must not swallow the newline.

    An exclusive motion reaches one past the last character, so on
    the very last word of the file `dw` takes all of it. Go to the
    end with G$ and check — this used to leave one character.

 Case, over the same motions and objects:
[x] gUw  upper-case a word     [x] guw  lower-case it
[x] g~w  swap case over a word
[x] 2gUw  two words            [x] gU2w  the count either side
[x] gUiw  over a text object   [x] gUi(  over a parens block
[x] gUt,  over a find
      make this shout, then quieten it down again
[x] gUU  this whole row        [x] gUgU  the long form
[x] guu  [x] g~~  the same for lower and swap
[x] 2guu  this row and the next

    Case changes do not touch the register: yank something, then
    gUW, then p — you should get what you yanked. Watch reg[] in
    the status bar stay put.

    gUiw on `straße` gives STRASSE — one character becoming two is
    why these go through the full Unicode mapping.

--------------------------------------------------------------
 7A. SHIFT — host-configured indentation
--------------------------------------------------------------

[x] >>  shift this row right       [x] <<  shift it left
[x] 3>> shift this row and two more
[x] >j  shift this row and the next
[x] >ip shift a paragraph          [x] >i{ shift a braces block
[x] Vj> shift a visual line selection
[x] >> then .  repeat the shift
      one row to indent
      second row to indent

    Watch the effect log: one Edit per changed row, but one `u`
    restores the whole shift. Empty rows stay empty; whitespace-only
    rows do move. `>w` still shifts its whole row, because shift is
    always linewise. The host's Indent configuration chooses shift and
    tab widths, plus whether new indents use tabs.

 8. TEXT OBJECTS
--------------------------------------------------------------

      the quick brown fox jumps
[x] diw  inner word          [x] daw  a word, plus a space
[x] ciw  change inner word   [x] caw
[x] yiw  yank inner word
[x] diW  inner WORD          [x] daW

      call(one, two) and more
[x] di(  inner parens        [x] da(  including them
[x] di)  same thing          [x] dib  the `b` alias
[x] ci(  change inside

      block { nested { deep } here } end
[x] di{  inner braces — nesting-aware
[x] da{                      [x] diB  the `B` alias
      list [ one, two ] and array [ three ]
[x] di[                      [x] da[
      generic <T, U> here
[x] di<                      [x] da<

      say "hello there" and 'goodbye' and `tick`
[x] di"  inner double quotes [x] da"
[x] di'                      [x] ci'
[x] di`

[x] dip  inner paragraph — the blank-line-delimited block
[x] dap

 Seeking, when the cursor is in no pair at all:
      the cursor here, the parens (over there) after it
[x] di(  from the start of the row — it looks forward
[x] di(  from *after* the parens — nothing, vi never seeks back
[x] di{  from the row above a block, which is the useful one:
      fn example() {
          the whole body goes, from up on the signature
      }

    Quotes seek too, but only within the row — `di"` from the
    start of a row reaches a string later on it. Brackets seek
    across rows, quotes do not. That asymmetry is vi's.

    The braces stay put. When `{` ends its row and `}` owns its
    own, `di{` takes the body's rows and leaves the two braces
    where they were rather than pulling them onto one row. `ci{`
    then opens the row between them, which is what you want.

 Counts, which mean something different for each kind of object:
      outer { mid { deep } here } end
[x] di{   the innermost braces, from the cursor on `deep`
[x] 2di{  one level further out — a count climbs the nesting
[x] 2da{  the same, taking the braces with it
[x] 3di{  nothing to climb, so it rings the bell
[x] d2i{  the count works either side of the operator

    A count is the nesting level you want, counted from where you
    stand — so from *outside* a block it runs the other way:
  {
    one: {
      two: {
        three: {
        }
      }
    }
  }

[x] di{   from `outer`, the outermost braces ahead
[x] 2di{  one level *in* — the braces around `deep`
[x] 3di{  nothing nested that deep, so it rings
[x] 2di{  on `outer {a} {b} end` — siblings are not a level

      one two three four
[x] 2diw  a word and the space after it — whitespace is a run
[x] 3diw  word, space, word
[x] 2daw  two whole words
[x] 9diw  stops at the row's end rather than joining rows

[x] 2dip  a paragraph and the gap after it
[x] 2dap  two paragraphs, each with its gap
[x] 2di"  quotes do not nest, so the count is ignored
[x] v2i{  a count extends a visual selection the same way

 9. SINGLE-KEY EDITS
--------------------------------------------------------------

      mangle THIS text however you like
[x] x    delete the character under the cursor
[x] <Del> same
[x] X    delete the character before it
[x] rZ   replace one character with Z
[x] ~    swap case, and advance
[x] 3~   swap three
[x] J    join the next row onto this one
      join me
      to the row above
[x] p    put after      [x] P    put before
[x] 2p   put twice

    Yank a row with `yy` then `p`: it should land on a new row.
    Yank a word with `yw` then `p`: it should land inline.
    That difference is the register's `linewise` flag — the
    status bar shows it as reg[line] or reg[char].

--------------------------------------------------------------
 10. UNDO
--------------------------------------------------------------

[x] u     undo
[x] <C-r> redo

    An insert session is ONE undo step: type `ihello<Esc>` then
    `u`, and all five characters go together — while the effect
    log shows five separate edits. Both granularities at once is
    the whole point.

--------------------------------------------------------------
 11. DOT REPEAT
--------------------------------------------------------------

[x] .    repeat the last change
      repeat me and me and me and me
      ciwX<Esc> then w then . then w then .
[x] 3.   repeat three times

[ ] Vj> then jj then .   the shift repeats over two more rows
[ ] Vjd then .           two rows, then two more
[ ] vwcX<Esc> then w then .

    `.` after an insert session replays the typed text.
    Note: `3.` replays the whole command three times rather than
    substituting the count, which differs from vi.

    After a visual operator, `.` replays the keys that made the
    selection, so `Vj>` repeats as `Vj>` — the same two rows from
    wherever the caret now is. That matches vi for whole rows. For
    a characterwise selection it re-aims the motion rather than
    repeating a character count, so `vwd` then `.` deletes to the
    next word boundary rather than the same number of characters.

 13. VISUAL MODE
--------------------------------------------------------------

      select some of this line and act on it
[x] v then motions — the highlight follows
[x] vd   delete the selection      [x] vx  same
[x] vc   change it                 [x] vs  same
[x] vy   yank it
[x] viw  extend to inner word
[x] va(  extend to a parens block
[x] v then V — switch granularity mid-selection
[x] V then j then d — delete whole rows
[x] <Esc> cancels without acting

    The selection includes the character under the cursor, so
    what you see is what gets deleted.

 Case, on the selection rather than one character:
[x] vwU  upper-case it     [ ] vwu  lower-case it
[x] v$~  swap case across the selection
[x] VjU  two whole rows
[x] vwgU  the operator form works here too

    `u` in visual mode is a case change, not undo — that is vi, and
    it surprises people. `~` covers the whole selection instead of
    the single character it takes in normal mode.

 15. VIEWPORT
--------------------------------------------------------------

[x] <C-d>  half page down   [x] <C-u>  half page up
[x] <C-f>  page down        [x] <C-b>  page up
[x] zz     centre the cursor row
[x] zt     cursor row to the top
[x] zb     cursor row to the bottom
[x] H      top visible row  [x] M middle  [x] L bottom
[x] 2H     second visible row      [x] 2L second from bottom

    The core does not own the viewport. The harness reports its
    current top row and height whenever it draws; that lets page
    keys carry the cursor while it still emits a Scroll effect for
    the host to fulfil. Full pages retain two rows of overlap.

    Put the cursor on a long line, press $, then <C-d>: it stays at
    the end after moving. H, M and L go to the first non-blank of
    the reported visible rows, so scroll the file before trying H.

 18. MARKS
--------------------------------------------------------------

[ ] m{a-z}   set a named mark
[ ] `{a-z}   jump to its exact offset
[ ] '{a-z}   jump to its row's first non-blank
[ ] `<   [ ] `>   last visual selection's start and end
[ ] '[   [ ] ']   last change or yank's start and end
[ ] `^            where insert mode last ended
[ ] ``   [ ] ''   return to the position before the latest jump

    Marks survive edits. ` and ' are motions, so try d`a and d'a
    to confirm their characterwise and linewise operator behaviour.

--------------------------------------------------------------
 19. JUMP LIST
--------------------------------------------------------------

[ ] <C-o>  jump back       [ ] <C-i>  jump forward
[ ] G gg H M L %   leave a jump
[ ] <C-d> <C-u> <C-f> <C-b>   leave a jump when they move

    The list remembers locations across edits. Insert text before a
    remembered place, delete text before one, then use <C-o> and
    confirm it still lands on the intended text.

--------------------------------------------------------------
 20. SEARCH
--------------------------------------------------------------

[ ] /pattern<CR>   search forward
[ ] ?pattern<CR>   search backward
[ ] n              repeat in the same direction
[ ] N              repeat in the reverse direction
[ ] 3/foo<CR>      third match      [ ] 3n  third repeat
[ ] d/foo<CR>      exclusive operator target
[ ] <BS> edits the pattern          [ ] <Esc> cancels it

    Search wraps at either end. An all-lowercase pattern ignores
    case; any uppercase letter makes it case-sensitive. Matching
    is literal, not regex. Successful searches leave a jump.

--------------------------------------------------------------
 21. SURROUND
--------------------------------------------------------------

[ ] cs({   change (foo) to { foo }
[ ] cs()   change ( foo ) to (foo)
[ ] ds(    delete parens; ds) is the same
[ ] v...S( surround a selection as ( selection )
[ ] v...S) surround a selection as (selection)
[ ] V...S) surround whole selected rows
[ ] .      repeat the last cs, ds, or visual S
[ ] u      undo both delimiter edits together

    Opening delimiter keys add one inner space; closing keys and
    quotes do not. Existing one-space padding is removed before a
    change or delete, so padding does not compound. Targets accept
    either side of a pair, plus b for () and B for {}. ys is not
    implemented and should ring.

--------------------------------------------------------------
 22. EDGES
--------------------------------------------------------------

    Multibyte — `x` must delete a whole grapheme, and the cursor
    must never land mid-character. The status bar shows the byte
    offset, so watch it jump by more than one.
      café niño — touché
      日本語のテキスト
      flags 🇦🇺 and family 👩‍👩‍👧‍👦 emoji

    Tabs — display width is the harness's job, not the core's.
    The byte column and the screen column will differ here.
      	one tab
      		two tabs
      a	middle	tab

    Empty rows — motions and operators over nothing.

[ ] dd on the blank row above
[ ] x on an empty row      [ ] J onto an empty row
[ ] $ on an empty row      [ ] diw on an empty row

    Trailing newline — go to the last row with G and try dd, o,
    and A. The file may or may not end in a newline; both should
    behave.
